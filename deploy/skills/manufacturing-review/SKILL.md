# manufacturing-review

When asked to review the project for manufacturing, check what makes a fab ask questions or refuse, not the circuit: DRC against the fab's limits, taken from the backplane tool `fab_profile` (the project's fab, board kind and options: each limit with its source and date), never from memory; `fab_profile` with action "drc" puts them in the project's DRC rules (tracks and gaps, vias, rings, hole and edge clearances, silkscreen: a value under a limit's free value but within the one that costs more is fine but costs more, so say so rather than calling it an error; under both, it must change; where Backplane recommends more than the fab's limit, a design between the two is a note, not a must-change, "meets the fab's 0.2 mm, under the recommended 0.3 mm": fab_profile gives Backplane's recommended value with each limit it has one for, as `recommended`), every BOM line has a manufacturer part number that is in stock (pcbparts tools; prefer basic/preferred parts, name extended ones), parts on one side for the cheaper assembly, footprint rotations sane, an outline that is closed, every part to order has a current fab file; for printed parts walls 1 mm or more (0.8 for SLA), for sheet metal flanges at least 4x the thickness and holes at least the thickness from a bend, for CNC inside corners with radii of 1 mm or more and no undercuts. A part whose fab file has a `sendcutsend` block is made for SendCutSend: check it with the sendcutsend skill (`scs.py dfm <its fab file>`, against SendCutSend's live specs), give each failed rule with its source, and call the check stale when the part file no longer matches its `dfm.source_sha256`. Run every check in the foreground (no background commands, monitors or waits) and keep each one short. Start with the backplane tool `design_review` (scope "order"): its findings are the deterministic part; then `design_review` with scope "judged" and record your datasheet checks with `design_review_judged`. Write the findings to `.backplane/review.md` (per part: what is fine, what must change and why), then call the backplane tool `order_review` with action "record", verdict "ok" when nothing must change or "issues", a one-line summary and issues: what must change, one short line each ("Shade: walls 0.6 mm, need 0.8 for SLA"). Your last message is what the thread that asked hears: make it that list and the link `.backplane/review.md`, then end. Change nothing while reviewing: say what must change; the person decides. Call the manufacturer "the fab", never by name, except SendCutSend for the parts made for it.
