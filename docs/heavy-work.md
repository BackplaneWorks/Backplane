# Heavy work admission

`scripts/check.sh`, `scripts/test.sh`, `scripts/build-js.sh` (except `--key`), `scripts/build-mobile.sh` and the build modes of `scripts/dev.sh` use the same native `bend` flock as Backplane's lock manager. A second local command cannot start while that lock is held. Child commands inherit the lock descriptor; the guard verifies the descriptor against the actual lock file. Checks and tests run with one job and one check shard.

The guard checks host available memory and, on Linux cgroup v2, every ancestor's remaining memory allowance. The available-memory floors are 12 GiB for checks, tests and browser work, 14 GiB for builds and 18 GiB for proof. These are conservative admission floors, not guarantees or process memory caps. Unreadable memory information fails closed. The measured baseline was roughly 8.2 GiB for the required tests and 13.2 GiB for a fresh server emit; a proof used roughly 13.6 GiB in one earlier run, so it has a larger margin. Individual source trees and toolchains can use more.

When local admission fails, a clean checkout may send supported, portable commands to one new Boat sandbox, using live Boat admission and `--wait 0 --no-reuse`. Check, test, JS build with a relative output path, mobile JS build, and `dev.sh web` have declared remote outputs. Dirty checkouts, commands with nonportable outputs, unavailable Boat admission and commands with baked credentials fail closed; the guard does not upload them. Boat logs and artifacts remain in the job's state directory and are not silently copied into the source tree. Remote guard refusal does not recursively start another sandbox.

For direct Bend, Bun or browser E2E commands use `scripts/heavy COMMAND ...` from the repository. This wrapper takes the native lock and applies the same memory checks. The automatic Boat fallback currently supports only the listed repository scripts; a direct command that cannot be safely transferred refuses rather than uploading arbitrary paths or data. **Raw commands that bypass these entry points are not intercepted.** In particular, invoking an absolute Bend or Bun binary directly, or launching an arbitrary browser E2E directly, is not protected by this change. Complete machine-wide enforcement requires control of every command launcher or OS-level policy.

A job already holding the native lock through an external Backplane `work_run` guard cannot pass the descriptor into these scripts, so these scripts will not mistake that external lock for their own. They may offload or refuse. A job that invokes the guarded entry point itself owns the same native lock for its local work. The guard does not stop already-running jobs.
