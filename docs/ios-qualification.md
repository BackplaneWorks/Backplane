# iOS simulator qualification

Use an isolated checkout and a new simulator for each run. This workflow builds the normal Debug app and leaves existing simulators and their data alone. It does not archive, upload, install on a physical device, restart a hub, or generate demonstration data.

1. Record the exact integrated commit and obtain the bridge built from that source by its owner; verify its SHA-256. Copy `mobile/ios` to a unique Mac directory such as `~/backplane-ios-vc-655983`, and put the verified bridge at `Backplane/bridge.js`. Do not overwrite a shared source copy or copy signing material. Record how the source copy was verified against the commit; the script records the supplied commit but cannot prove the copy matches it.
2. Inspect `xcodebuild -version`, `xcrun simctl list runtimes`, and `xcrun simctl list devicetypes` on the Mac. Run `test/ios-vc/build-simulator.sh` from that copy with `SOURCE_COMMIT`, `BRIDGE_SHA256`, `SIM_DEVICE_TYPE`, and `SIM_RUNTIME` set. Run the Mac job under the `ios-vc-mac` named lock. The script builds, creates a new named simulator, boots and installs; it writes its UDID, build log, executable and bridge hashes, and Xcode/runtime information under `qualification-evidence`. It does not launch or pair the app.
3. Verify the selected existing hub independently via its read-only `/hello`, and record its nonsecret address, version and commit, plus the real project and thread used. Pair only through an existing secure channel or the app's pairing screen. Do not record pairing links, tokens, logs containing them, or screenshots that expose them. A new simulator has separate client state; do not reset shared hub authentication or data.
4. Record actual observations, timestamps and sanitized screenshots/video for first pairing, cold and warm launches, persistence after relaunch, repeated project/thread navigation and viewer entry/exit, background/foreground, an app-only connection interruption and recovery, invalid session and cancellation. Only exercise read-only interactions with real data. Record each result as pass, fail or not tested, including the action and observable outcome; do not infer success from a build or from a screenshot alone. An interruption must affect only the isolated client, never shared network or hub services.
5. Repeat against the exact integrated source and bridge; record source and executable hashes and the simulator/runtime. Keep simulator artifacts private when they contain real data. Simulator results do not establish physical device performance, GPU/Metal behavior, thermal behavior, or production distribution readiness.

The existing `scripts/build-ios.sh sim` selects a booted simulator and synchronizes a shared directory by default, so do not use it for this isolated run. The build script above is preparation, not UI automation or evidence of acceptance; use available XCTest or another installed UI driver for observed interactions and record any missing coverage explicitly.

## Isolated XCTest preparation

`test/ios-vc/add-ui-test-target.py DISPOSABLE_IOS_COPY test/ios-vc/QualificationUITests.swift` adds a UI-test target and scheme only to a source copy whose directory name begins `backplane-ios-vc-655983`. The generator does not modify the checked-in Xcode project. `QualificationUITests.testFreshSimulatorShowsPairing` checks the initial empty pairing screen. After that test, enter or paste the real pairing link through the normal app UI using a secure channel, and complete pairing. Do not put the link in a test configuration, shell argument, `BACKPLANE_LINK`, captured screen, log, or result bundle. Run `QualificationUITests.testPersistedPairingAndNavigation` separately with no pairing override: it checks a real thread opens and relaunches the app to check that pairing survives. Keep test result bundles private because they can contain real project content.

The target generator has been accepted by Xcode's project listing; compiling and running these tests remains a separate required check. These two initial tests do not cover all viewer, failure, interruption, or timing cases in the qualification checklist above.
