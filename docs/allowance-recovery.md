# Remaining provider allowance recovery

The model bar shows remaining reported provider allowance, with a details panel for pool scope, source, last reading and reset. Token/cost totals on Usage remain separate. Unknown providers, unsupported account types and missing or invalid readings stay unknown. Shared pools are labeled shared; different provider bucket IDs and different profiles are never summed or assigned to a model.

The default Codex CLI source uses the recovered read-only app-server collector. It has a five-minute cache gate, private cache/lock, bounded supervised child and same-identity stale-data retention. It performs no model prompt or explicit token refresh. Default Claude readings come only from passive stream windows. Named profiles use the existing accounts inventory, gated by the thread's exact provider, profile and identity generation; they never borrow the default CLI quota. Their existing account collector owns refresh and passive observation. Opening the panel only displays state. An explicit default Codex check is a single background worker and bypasses voice preference persistence.

A current default reading lasts at most fifteen minutes; named metadata lasts at most five minutes. A reported reset retires the display immediately rather than assuming a refill. Bend supplies the exclusive presentation deadline. The browser can only retire a chip/panel, including cached or unready pictures; its timer makes no provider read and calculates no quota. A new server picture is required to show a current value again.

Native allowance adoption remains separate. This change adds no mobile source/schema, native package, authentication change or installation.
