# Viewer Rail Map (Baseline on `main`)

Factual inventory of the desktop right rail (`native/gpui/src/ui.rs`), viewer pane (`native/gpui/src/screens/viewer.rs`), and hub presenter (`native/host/src/present/viewer.rs`) as observed in code and measured by `test/viewers/rail-shots.sh`.

## Rail Entries (Top to Bottom)

On desktop GPUI, the right rail (`72 px` wide, `ui.rs`) is a static list except for **Simulation**, which renders only when the hub reports `viewer.simFrame` and the window can host local KiCad. Every other entry renders on all four project kinds (`full`, `schematic-only`, `mech-only`, `no-design`).

## Pane States & Known Inconsistencies (Observed)

- **Idle (viewer shut):** Pane is absent (`Empty`); thread takes full width between sidebar and the `72 px` right rail.
- **Pane-level controls leak onto non-design pages and non-design projects:** `pane_actions` checks `has_design(viewer)` (true whenever `viewer.choices` includes `board` or `schematic` — which the hub's static template includes even on `mech-only` and `no-design` projects), so `Open in KiCad` appears on **Files**, **Review**, **Mech**, and **Browser** across all four project kinds (suppressed only on `diff` and `gerbers`).
- **Refused views leave stale red error text:** Pressing **Gerbers** on `schematic-only`, `mech-only`, or `no-design` (no `mfg/` Gerber set) refuses with `View request refused: "PRESENTER_UNAVAILABLE"` under the thread; the rail stays on the previous entry (`3D`) and the red error line persists across subsequent page switches.
- **Split after Mech on `mech-only`:** Switching from **Mech** (`bracket.step`) to **Split** leaves Split's 3D sub-pane stuck on `"Loading the model…"` because `solid_ready` sees Mech's key while no board exists.
- **`schematic-only` with `.kicad_pro`:** Background KiCad embed prewarm launches KiCad against the `.kicad_pro`, which pops up a modal `"PCB '...kicad_pcb' does not exist. Do you wish to create it?"` dialog over the window.
- **Header layout differs across pages:** Board/Schematic/Gerbers/Files/Diff/Review/Mech use a `bar_wrap` row (`ROW_H`; Gerbers wraps to 2 rows with its note and `×` on row 2), Split uses a fixed-height `split-bar` with its own pane toggles, while 3D and Browser draw edge-to-edge with `pane_actions` floating `in_corner` top-right.
- **Embedded KiCad editor (`ui:Edit`):** Replaces Board/Schematic/3D body with `KicadPane` under a two-row header: `bar(light)` (`[Boards]`, `View`, `×`) plus `kicad_pane::strip` (editor tabs, `Full size`, `Full screen`, `Pop out`).
- **Management strip (`screens/mgmt.rs`):** Renders a `24 px` bottom strip (`BOM`, `Checks`, `Lifecycle`, `Plan`, `Fab`) on Board, Schematic, 3D, Gerbers, and Split, overlapping with Review's tabs (`BOM`, `Checks`, `Comments`, `Release`).
- **Mobile parity gap:** iOS (`DataViewer.swift`) and Android (`DataViewer.kt`) hard-code `["Board", "Schematic", "3D", "Split", "Mech", "Files", "Diff", "Review", "Browser"]` (no `Gerbers`, no `Simulation`, not driven by a single hub rail list).
