# Viewer Rail Map (Baseline on `main`)

Factual inventory of the desktop right rail (`native/gpui/src/ui.rs`), viewer pane (`native/gpui/src/screens/viewer.rs`), and hub presenter (`native/host/src/present/viewer.rs`) as observed in code and measured by `test/viewers/rail-shots.sh`.

## Rail Entries (Top to Bottom)

On desktop GPUI, the right rail (`72 px` wide, `ui.rs`) is driven by the hub's `viewer.rail` list (since PR #1328), with a static fallback only for older hubs. Entries whose resource is absent on the current project render dimmed (`state: "disabled"`, 45% opacity, tooltip `why`, not clickable); **Gerbers** is hidden when no Gerber set exists; **Simulation** renders only when the hub reports `viewer.simFrame` and the window can host local KiCad. Follow agent (`viewer.follow`, `present/viewer.rs`) is emitted by the hub only on **Board**, **Schematic**, and **Split**.

## Pane States & Observed Inconsistencies

- **Idle (viewer shut):** Pane is absent (`Empty`); thread takes full width between sidebar and the `72 px` right rail.
- **Pane-level controls leak onto non-design pages and non-design projects:** `Open in KiCad` appears on **Files**, **Review**, **Mech**, and **Browser** across all four project kinds (including `mech-only` and `no-design`), suppressed only on `diff` and `gerbers`.
- **Refused views leave stale red error text:** Pressing **Gerbers** on `schematic-only`, `mech-only`, or `no-design` (no `mfg/` Gerber set) refuses with `View request refused: "PRESENTER_UNAVAILABLE"` under the thread; the rail stays on the previous entry (`3D`) and the red error line persists across subsequent page switches.
- **Split after Mech on `mech-only`:** Switching from **Mech** to **Split** leaves Split's 3D sub-pane stuck on `"Loading the model…"`.
- **`schematic-only` with `.kicad_pro`:** Opening Board triggers KiCad embed warm-up (`native/host/src/kicad/embed.rs` `Msg::Warm` with `frame: "PCB"` even though no `.kicad_pcb` exists), popping up a native modal `"PCB '...kicad_pcb' does not exist. Do you wish to create it?"` over the window.
- **Header layout differs across pages:** Board/Schematic/Gerbers/Files/Diff/Review/Mech use a `bar_wrap` row (`ROW_H`; Gerbers wraps to 2 rows with its note and `×` on row 2), Split uses a fixed-height `split-bar` with its own pane toggles, while 3D and Browser draw edge-to-edge with `pane_actions` floating `in_corner` top-right.
- **Embedded KiCad editor (`ui:Edit`):** Replaces Board/Schematic/3D body with `KicadPane` under a two-row header: `bar(light)` (`[Boards]`, `View`, `×`) plus `kicad_pane::strip` (editor tabs, file-conflict controls `Keep yours` / `Reload (lose your edits)`, long-job progress bar with cancel, checks chip, stock-KiCad note, KiCad notice, and `Full size` / `Full screen` / `Pop out`).
- **Management strip (`screens/mgmt.rs`):** Renders a `24 px` bottom strip (`BOM`, `Checks`, `Lifecycle`, `Plan`, `Fab`) on Board, Schematic, 3D, Gerbers, and Split — separate from Review's own tabs (`BOM`, `Checks`, `Comments`, `Release`).
- **KiCad `.lck` lock files shown in the Files page:** On projects with a KiCad board or schematic, the **Files** page lists KiCad's temporary lock files (`~ecc83-pp.kicad_pcb.lck`, `~ecc83-pp.kicad_sch.lck`), whose contents can include the host's user name and hostname. The harness records what the app really shows rather than hiding them in fixtures; the Files page (or hub file listing) should filter KiCad lock files.
- **Mobile parity gap:** iOS (`DataViewer.swift`) and Android (`DataViewer.kt`) hard-code `["Board", "Schematic", "3D", "Split", "Mech", "Files", "Diff", "Review", "Browser"]` (no `Gerbers`, no `Simulation`, not driven by a single hub rail list).

## Privacy & `--share` Scope

- Fixture repos run through an atomic mode-`0700` alias directory under `/var/tmp/bp-rail.XXXXXX` (pointing to `$BP_TMP`) so project paths carry no OS user name.
- Any shot with a visible native dialog (`obstructed: true`) or user-identifying path in metadata is marked `"private": true` in `steps.json` and excluded from **every** derived image (`contact-<kind>.png`, `headers.png`, `rails.png`, and `--compare` pairs).
- **Canvas limitation:** metadata scanning cannot see a path drawn inside an editor or simulator canvas (e.g., KiCad's SPICE console or status bar), so `--embed` shots of KiCad (`task8-edit`, `task7-sim`, `task7-sim-run`) are marked `"private": true` by default unless a path-free fixture is proven. `--share` refuses any run or comparison that contains a private shot or lacks complete schema-2 privacy metadata.
