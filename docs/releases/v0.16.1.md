# Backplane 0.16.1

0.16.1 brings the new Backplane KiCad (bp.13.1) to every computer, which puts KiCad in the pane on the Mac and brings KiCad's standard libraries and Backplane's own to Windows and Mac. It also fixes the issues 0.16.0 listed. If you run 0.16.0 or 0.15, it offers this update; your threads and settings carry over as they are.

## Backplane KiCad bp.13.1

When you press **Edit** next, a row above the editor offers the update, with what it brings and its size: **Update**, or **Not now** (asked again a day later). It reopens on the new version by itself unless you have unsaved changes. Settings → CAD offers it too.

- **On a Mac, KiCad opens in the pane,** as on Linux and Windows.
- **KiCad's standard libraries and Backplane's own** come with it on Windows and Mac, registered on a fresh install and added to your existing tables on update. A library you removed stays removed.
- **No more OpenGL box on Windows** computers without OpenGL 2.1 graphics (some virtual machines and remote desktops): KiCad draws in software by itself and says so in the pane.
- **In a narrow pane, KiCad's side panels fold away** so the board keeps most of the room; they come back at full size.
- **Fixed in the embedded editor:** on Windows, Ctrl+S after a click on the canvas, and Ctrl+W now closes the editor; on a Mac, undo, redo, copy to the clipboard, paste and zoom keys, and Cmd+O no longer opens another project inside the pane; on every computer, the "Incomplete undo/redo operation" box, and undo and redo stopping after one of Backplane's automatic checks until you clicked the board.
- **A crash fixed:** the embedded board editor could crash when you had selected everything, DRC markers included, and a check then ran. On Windows, the crashed KiCad was also restarted outside Backplane with KiCad's first-run setup; it no longer is, and the pane says KiCad closed unexpectedly with **Open the editor again**.

## Fixes

- **On older Linux systems, agents start again.** On Ubuntu 22.04 and 20.04, Debian 11 and 10, and other systems with systemd 249 or older, or with no user systemd at all (many containers, WSL), 0.16.0 failed every turn with "agent exited with code 1" or "Unknown assignment: OOMPolicy=continue". Backplane now checks what your systemd supports and uses only that, or starts agents without a scope, so `BACKPLANE_NO_SCOPE=1` is no longer needed.
- **Backplane KiCad no longer shows KiCad's first-run setup wizard.** Its settings start out with KiCad's own update checks and data collection off. A KiCad you installed yourself is left as it is.
- **The agent picker shows the agents you actually have.** With only Codex installed, the picker ticked Claude and called Codex "not installed" while Settings showed it connected. It now uses the same check as Settings and setup, runs it again the moment a CLI is installed, updated or signed in, and starts new threads on an installed agent. An agent CLI older than the version Backplane was tested with shows **update needed** with an **Update** button; it still works.
- **Signing in to Codex no longer stays at "Signing in".** A sign-in that Codex saved without telling Backplane now finishes, and a Codex account whose sign-in was interrupted by a restart picks it up.
- **On macOS, KiCad version checks that never finished no longer pile up in the background:** each is stopped after 20 seconds and tried once more.
- **Creating a thread** (+ beside a project, or New thread on a project's page) now opens it with the text box ready to type, also in projects with many threads; on the phones the new-thread box is focused.
- **Closing the embedded editor** with Cmd+W or Ctrl+W always takes the pane back to the viewer, and **Edit** opens it again. On a Mac the pane could stay blank and Edit did nothing.
- **Agents can't open KiCad windows on your desktop.** They edit only through Backplane's KiCad tools, inside the pane.
- **If you turned anonymous usage Off in 0.14, it stays Off.** Importing a 0.14 home used to lose that choice and ask again. A home already imported that way is put back to Off once, before anything is sent, when the 0.14 home still says Off and you haven't chosen On since.

## Installing

- **macOS** needs a Mac with Apple silicon (M1 or later) and macOS 13 or later; Backplane KiCad needs macOS 15 or later. Intel Macs aren't supported.
- **Linux and macOS:** `curl -fsSL https://github.com/BackplaneWorks/Backplane/releases/download/v0.16.1/install.sh | sh`, or press **Update** in the app.
- **Windows:** extract the zip and open `backplane-gpui.exe`, or press **Update** in the app.
- **Android:** install `backplane-v0.16.1-android.apk`. It installs over 0.16.0.
- **iPhone:** through TestFlight.

## Known issues

- **Windows:** the programs aren't code-signed yet, so SmartScreen warns on first start.
- **Windows:** in the embedded schematic editor, after one of an agent's checks, click the canvas once before KiCad's shortcuts work again.
- **Windows:** while some of KiCad's own dialogs are open in the embedded editor (Board Setup, or Save As), Backplane's window doesn't take clicks or typing until you close the dialog, as KiCad's own window doesn't. Backplane keeps drawing, and everything works again once the dialog closes.
- **macOS:** the app isn't notarized yet. Installed with the command above it opens normally; if you unpack the archive by hand, open Backplane once with right-click → **Open**.
