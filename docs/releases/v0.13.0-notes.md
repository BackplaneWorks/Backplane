Draft release notes for Backplane 0.13 (v0.13.0), for the GitHub release body. The signed Android APK for it is on the nightly v0.13.0-nightly.20261028.1 (0.13.0, version code 2026102816, built from fa61a40a9).

---

Backplane 0.13 is a step change: Split view with cross-probing between the board, the schematic and the 3D model, a single top bar, a keyboard-first workspace, a much improved layout skill, Buy it on by default, and a long list of fixes from an overnight polish pass. It updates the desktop app, the server, the web client and Android, and moves the KiStack pin.

What's new:
- **Split view and cross-probing**: the schematic, the board and its 3D model side by side, each pane put away and back; click a part or a net in one and it lights in the others (a probed net outlines its pads, not its pours), and the probe stays across closing the viewer, switching tabs and reloading. The first probe is as quick as the next.
- **A much improved layout skill**: KiStack's layout-placement skill places by function, routes and checks DRC; the KiStack pin moves to 641ade9.
- **One top bar** for the window's chrome (breadcrumb, State cell, command field, Settings gear); its dot turns red while the hub is unreachable, State says stopped after Stop and failed (with the reason) when an agent fails, and opening a thread no longer flashes "idle".
- **Model picker in three columns** (agent, model, effort), keyboard first.
- **Keyboard first**: the composer keeps the keyboard; Esc closes the open menu or dialog, then puts away the terminal or the viewer; `/` brings the keyboard back to the composer; workspace shortcuts work from text fields; keycaps (rail keys, thread digits, the shortcut legend) show while Ctrl is held.
- **Buy it** is on by default, for people updating too (unless they turned Ordering off), and sits at the foot of the tool rail; rail buttons toggle their view.
- **Status colours**: working blue, finished green, needs-you red; each sidebar row says whether it is settled, pinned or when it wakes.
- **Settle when done** is a setting: finished threads stay active unless it is on; a thread that settles while open stays in sight.
- **Intent menu**: a project's intent opens from its menu (Enter for new lines, says when saved) instead of sitting above every thread.
- **Search across threads**: finds a word in every thread, the open one's first, and opens a result at its message; the command palette puts the best match first and lists only commands that apply.
- **No flashes, steadier scrolling**: switching threads goes straight from one to the other, a reload keeps the page frame and the open viewer, history pages keep the text in place, and a "New ↓" pill takes you to the end.
- **Design history**: Play waits for each step to draw, stepping keeps the board on screen, and the change counts agree.
- **Diff and Review**: an open Diff refreshes as the thread's changes move on, says when a folder is not a git repository, greys out git actions with nothing to commit; the Review BOM table fits the viewer.
- **3D**: lit from above on a soft spot of light; a board's model is kept on the hub (a reload shows it at once) and prepared when its board opens; one model is read at a time, and a model too big for the hub's memory is refused with a note.
- **Routines** fire at their time, not at the next minute's tick.
- **Settings** uses a wide screen; the projects sidebar folds from its own chevron to a strip of project initials, and on a narrow window it opens as a drawer beside the viewer.
- **Android**: streaming replies are followed, the composer's Stop stops every time, failed turns say why, the row menu's Fork and Merge reach the right thread, search results open their message, fast typing keeps every key, multi-board projects can pick a board, and API keys reach the hub only at Save.
- **Security**: API keys, Google's client secret, voice and Antigravity keys and pasted machine invites stay out of the web page's view and replies.

Downloads include four desktop packages, web, classic updater-compatible archives, Linux installers, the signed Android APK, SHA256SUMS and source/artifact provenance. Desktop packages follow the existing unsigned-portable policy. The APK (0.13.0, version code 2026102816) is signed with the existing release key (signer ef21acdb…906e), so it installs over earlier Backplane APKs.

How it was checked: each change was checked with targeted Bend tests and by driving the real UI against isolated test hubs with stand-in agents: end-to-end user stories on the web page, the desktop app and the Android app (an emulator, with a locally built APK of the same code). The release-signed APK was checked by its workflow (signer, version and embedded bridge), not run on a device. CI's check/test/build did not run on these commits, and broad regression, a full proof campaign and native desktop smoke were not run; the existing full-proof late-import parse blocker remains recorded.

Known: reading a board's 3D model can take a few GB of memory for a moment, and models over 12 MB are not shown; the two-second first-useful startup target remains unmet; no RF validation is claimed for the layout skill.

iOS is unchanged: the existing signed iOS 0.12.2 build 202610242215 remains current. This release adds no store upload, tester or external beta-review action.
