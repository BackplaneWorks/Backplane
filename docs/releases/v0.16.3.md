# Backplane 0.16.3

0.16.3 is the first release after 0.16.0. 0.16.1 and 0.16.2 were never released, so everything they were going to bring is here as well. 0.16.3 brings Backplane KiCad bp.13.1 to every computer, which puts KiCad in the pane on the Mac. It adds Altium Designer projects next to KiCad ones and a copy button wherever there is text to copy. Every project now gets git snapshots you can restore from. There are also many fixes to the embedded editor and to agents. If you run 0.16.0 or 0.15, Backplane offers this update. Your threads and settings carry over as they are.

## Backplane KiCad bp.13.1

The next time you press **Edit**, a row above the editor offers the update, with what it brings and its size. Choose **Update**, or **Not now** (you're asked again a day later). KiCad reopens on the new version by itself unless you have unsaved changes. Settings → CAD offers the update too.

- **On a Mac, KiCad opens in the pane,** as it does on Linux and Windows. Pressing Backplane's window no longer leaves the pane blank.
- **KiCad's standard libraries and Backplane's own come with it on Windows and Mac.** They're set up on a fresh install and added to your existing library tables when you update. A library you removed stays removed.
- **No more OpenGL message box on Windows computers without OpenGL 2.1 graphics** (some virtual machines and remote desktops). KiCad draws in software by itself and says so in the pane.
- **In a narrow pane, KiCad's side panels fold away** so the board keeps most of the room. They come back at full size.
- **Fixed in the embedded editor:**
  - On Windows, Ctrl+S works after a click on the canvas, and Ctrl+W closes the editor.
  - On a Mac, undo, redo, copy, paste and the zoom keys work, and Cmd+O no longer opens another project inside the pane.
  - Everywhere: the "Incomplete undo/redo operation" box is gone, and undo and redo no longer stop after one of Backplane's automatic checks until you click the board.
- **A crash is fixed.** The embedded board editor could crash when you had selected everything, DRC markers included, and a check then ran. On Windows, the crashed KiCad was also restarted outside Backplane with KiCad's first-run setup. That no longer happens: the pane says KiCad closed unexpectedly and offers **Open the editor again**.
- **New Backplane KiCads can now reach you without a Backplane update.** Backplane reads which KiCad to offer from a signed feed, and each KiCad there says which Backplane it needs. Backplane KiCad bp.13.2 needs a later Backplane than 0.16.3, so it comes with that update.

## Altium Designer

Backplane now works with Altium Designer projects as well as KiCad ones.

- **Altium projects are recognised** (`.PrjPcb`). Their boards and schematics open in Backplane's viewers without Altium: schematic sheets with their parts, nets, text and sheet symbols, and boards with their outline, copper, pours, pads, vias and text. Repeated sheets and flat designs work, and the **BOM** panel reads them.
- **3D view of an Altium board,** read directly: embedded STEP models and extruded bodies are placed, and the solder-mask openings follow the board's rules. Parts convert small models first, and the 3D view takes priority over background work.
- **The phones open `.PcbDoc` and `.SchDoc` files** on the Board and Schematic tabs.
- **Open in Altium** on an Altium project's viewer. If Altium isn't running, it is started.
- **Agents can work in your running Altium (Windows).** With `altium_status` and `altium_script`, they inspect and edit projects: they can place parts, wires and labels, update the PCB from the schematic, autoroute, pour polygons and check design rules. They answer only the dialogs their own script expects, run one script at a time, and save as soon as they've made a change. They never discard your unsaved work in a dialog box, and they keep your window in front.
- **Agents can make Altium files without Altium,** on any computer: `altium_write` writes footprint libraries (`.PcbLib`), symbol libraries (`.SchLib`) and schematic sheets (`.SchDoc`) from a description.
- An Altium project's agents get Altium's instructions and a bundled Altium skill with tested recipes, instead of KiCad's.

## Projects and git

- **Every project is a git repository, and Backplane takes a snapshot before each turn.** You can restore a project to any of those snapshots, and a review of the changes opens read-only. If an agent's turn would delete many files at once, it asks you first. It asks only the person who started the turn, and the question expires after 5 minutes. A turn started by a bot, a subthread or a wake is refused straight away, with the reason. System and temporary folders are never made into repositories. (#1163)
- **Git is part of setup.** The Design tools row shows Git's version and installs it with one press: winget or Git for Windows' installer on Windows, Homebrew or the Command Line Tools on a Mac. On a Windows computer without Git yet, you can still add and create projects. (#1163)
- **Backplane no longer pushes to your git remote on its own.** Design files are still committed locally at the end of each turn. To push again, turn on Settings → Projects and git → **Push commits to the remote automatically**. While it's off, a project's page shows the commits that haven't been pushed, with a **Push** button. (#1171)
- **New setting: Keep Backplane's commits off my branch** (Settings → Projects and git, off by default). Design commits now have a subject line that says what changed.
- **Windows: creating a project no longer fails with "bp-sh: program not found"** after you install Git for Windows. Backplane finds Git without a restart, and when Git is missing it says plainly to install it.

## Copy and terminals

- **A copy button wherever text is meant to be copied:** on replies, notices, room and swarm posts and settings rows, on the desktop and both phones. Commands also get **Run in terminal**.
- **Every chat has its own terminal:** threads, bot chats, the uberbot's chat and rooms. On a bot's page, Ctrl+J and the Terminal button open that chat's shell. A chat without a project folder starts in your home folder.

## Agents

- **The agent picker shows the agents you actually have.** It uses the same check as Settings and setup, runs it again as soon as you install, update or sign in to a CLI, and starts new threads on an agent you have installed. An agent CLI older than the version Backplane was tested with shows **update needed** with an **Update** button, and it still works.
- **Speed in the model picker:** Normal, Fast or UltraFast, per provider and model. (#1166)
- **Every built-in agent has its own mark in the picker:** Codex, Grok, Muse, Antigravity, Pi and Oh My Pi, next to Claude and OpenCode.
- **A linked machine's thread can be steered from here.** The composer's model, effort, speed and agent pickers act on that machine's thread. (#1197)
- **Every agent on every provider gets the KiStack skills pinned with this Backplane,** never an older copy of your own.
- **Signing in to Codex no longer stays stuck at "Signing in".** A sign-in that Codex saved without telling Backplane now finishes. A sign-in interrupted by a restart picks up again after it. (#1162)
- **On older Linux systems, agents start again.** On Ubuntu 22.04 and 20.04, Debian 11 and 10, and other systems with systemd 249 or older, or with no user systemd at all (many containers, WSL), 0.16.0 failed every turn with "agent exited with code 1" or "Unknown assignment: OOMPolicy=continue". Backplane now checks what your systemd supports and uses only that, or starts agents without a scope, so `BACKPLANE_NO_SCOPE=1` is no longer needed. When the system refuses the scope straight away, Backplane always retries without it.
- **Agents can't open KiCad windows on your desktop.** They edit only through Backplane's KiCad tools, inside the pane.
- **Windows: `kicad-cli` runs from Git Bash and MSYS2.** (#1167)
- **A secret an agent asks for is hard to miss.** The request shows under Needs you, on your phone and in the uberbot's conversation, with one reminder after an hour.
- **Delete bot** removes the bot's threads, routines and home folder, and every client says so before it does. On the phones, Settings lists the bots you can delete. (#1161)

## KiCad fixes

- **An agent's save no longer looks like your edit on boards with zones.** After an agent saved a board that has zones, KiCad's zone refill counted as yours, so for the next two minutes the agent was told you were editing ("Fill Zone(s)") and stopped to ask you. The agent's own edit now does the refill before it saves. (#1224)
- **Moving around the embedded KiCad no longer blocks an agent's saves.** Panning, zooming or clicking in the pane used to count as an unsaved edit of yours. Agents' saves were then refused until you saved (and some agents added their tracks twice), or agents reported writing "your" unsaved changes. Now only a change you actually make counts as yours. (#1169)
- **KiCad's own windows work again after the embedded editor broke them.** An embedded KiCad could save window, panel and chooser sizes far off the screen into your KiCad settings, so KiCad opened outside Backplane with broken or invisible windows. Before it starts KiCad, while no KiCad is running, Backplane now removes just those entries, and it keeps a backup of each file it changes. (#1185)
- **A restart leaves KiCad locks from other computers in place.** On shared or synced folders, Backplane asks before opening a project whose lock belongs to another computer or has an unknown owner. It removes only stale locks written on this computer. A document another running KiCad holds is never opened over its lock. A DRC run then goes through `kicad-cli` instead, and if KiCad opens a file over a lock anyway, the strip says so.
- **Windows: KiCad survives Backplane's window closing.** Quitting Backplane, switching the pane to View or closing the viewer no longer takes the embedded KiCad and its unsaved changes down with it.
- **Windows: when one of KiCad's own dialogs is open, the strip names it,** instead of saying KiCad isn't responding.
- **Closing the embedded editor** with Cmd+W or Ctrl+W always takes the pane back to the viewer, and **Edit** opens it again. On a Mac, the pane could stay blank and Edit did nothing.
- **Backplane KiCad no longer shows KiCad's first-run setup wizard.** Its settings start with KiCad's own update checks and data collection off. A KiCad you installed yourself is left as it is.
- **On macOS, KiCad version checks that never finished no longer pile up in the background.** Each one is stopped after 20 seconds and tried once more. (#1160)
- **No second, hidden KiCad next to the editor.** A BOM edit opens the schematic out of sight in the editor's own KiCad.
- **`kicad_edit` refuses an HTTP library part that came in empty,** instead of placing a part with no body and no pins, and its answer says which KiCad served the call. (#1192)
- **"KiCad closed unexpectedly"** says unsaved work was kept only when KiCad's local history really holds a newer, different copy of the board or schematic.
- **Pressing a design tab** shows that page loading straight away ("Loading the board…"), instead of the page you were on.
- **Long designs:** a **Sheets** menu with a search field, keyboard navigation and each sheet's parent path, on the desktop and the phones.
- The project card's board list now matches the boards in the viewer.

## Also fixed

- **If you turned anonymous usage Off in 0.14, it stays Off.** Importing a 0.14 home used to lose that choice and ask again. Backplane now puts a home already imported that way back to Off, once and before anything is sent, if the 0.14 home still says Off and you haven't chosen On since.
- **A sent message leaves the box straight away**, so it isn't sent twice, and it stays in the chat until the hub has it. (#1233)
- **Windows: the app has the Backplane icon** on its windows, the taskbar and in Explorer, instead of the system's blank one. (#1228)
- **A phone alert that reaches no phone now says so.** Backplane used to report a notification as "sent" even when no phone could get it, for example when the push key is missing. Now the uberbot's conversation names the cause and how to fix it, and `notify_person` says the alert didn't reach the phone.
- **Creating a thread** (+ next to a project, or New thread on a project's page) opens it with the text box ready to type, also in projects with many threads. On the phones, the new-thread box gets focus.
- **The sidebar** has a setting for every thread (#1186) and one row per folder of a repository (#1168). Its hub picker can forget a hub.
- **One-line text fields** scroll with the cursor instead of running past their box.
- **Security:** a thread's Backplane tool key no longer appears on any agent's command line, where other programs on the computer could read it.

## Installing

- **macOS** needs a Mac with Apple silicon (M1 or later) and macOS 13 or later. Backplane KiCad needs macOS 15 or later. Intel Macs aren't supported.
- **Linux and macOS:** run `curl -fsSL https://github.com/BackplaneWorks/Backplane/releases/download/v0.16.3/install.sh | sh`, or press **Update** in the app.
- **Windows:** extract the zip and open `backplane-gpui.exe`, or press **Update** in the app. Windows may say "Windows protected your PC": choose **More info**, then **Run anyway** (the exe isn't signed yet).
- **Android:** install `backplane-v0.16.3-android.apk`. It installs over 0.16.0.
- **iPhone:** through TestFlight.

## Known issues

- **A part from an HTTP library can come in empty**, with no symbol body and no pins, when you place it yourself in the embedded KiCad (Choose Symbol, then place). It's a cache race in KiCad's HTTP library support, and a later Backplane KiCad fixes it. Until then, check each HTTP library part after you place it and replace any that came in empty. Agents' placements are refused instead (see above). (#1192)
- **macOS:** when KiCad offers to recover unsaved changes as it opens, the pane can stay stuck. The fix needs Backplane KiCad bp.13.2, which comes with a later Backplane update. 0.16.3 already has Backplane's half of the fix. (#1240)
- **macOS:** if you close the viewer while KiCad is open in the pane, KiCad's editor window can stay on screen over Backplane. To avoid it, close the editor with Cmd+W before you close the viewer. (#1199)
- **Windows:** in the embedded schematic editor, after one of an agent's checks, click the canvas once before KiCad's shortcuts work again.
- **Windows:** if Backplane's window is killed outright (from Task Manager, or by a crash), the embedded KiCad closes when Backplane comes back. Changes not yet saved are lost, except what KiCad's autosave offers back.
- **Windows:** while some of KiCad's own dialogs are open in the embedded editor (Board Setup, or Save As), Backplane's window doesn't take clicks or typing until you close the dialog, as KiCad's own window doesn't. Backplane keeps drawing, and everything works again once the dialog closes.
- **Windows:** the programs aren't code-signed yet, so SmartScreen warns on first start. Managed PCs may not allow them to run.
- **macOS:** the app isn't notarized yet. If you install it with the command above, it opens normally. If you unpack the archive by hand, open Backplane once with right-click → **Open**.
