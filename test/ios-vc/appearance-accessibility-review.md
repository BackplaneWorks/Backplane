# iOS appearance and accessibility qualification

Source baseline: 589638170f0d8a4abba3761c094e26de5cadf920. Tests are source-only until run against an exact integrated app and bridge. Existing `add-ui-test-target.py` accepts a single Swift file; pass `AppearanceAccessibilityUITests.swift` in a fresh dedicated Mac source copy to install this suite instead of the existing suite. The sole Mac runner controls builds and runs after the performance baseline, under the existing `ios-vc-mac` lock. Never run the general `scripts/build-ios.sh` for qualification: its simulator mode selects an existing booted device and its archive mode exports with destination upload.

Run the suite separately in light and dark appearance on the dedicated paired compact phone, and again on the smallest supported available iPhone with an accessibility text size selected in simulator settings. Record device/runtime, appearance, text size, exact app source and bridge hash. Use the test target's launch arguments for `-UIPreferredContentSizeCategoryName UICTContentSizeCategoryAccessibilityM` if applying the size in a dedicated test scheme; otherwise set it on the dedicated simulator. Restore any simulator preferences the runner changes. A separate reduced-motion run must have Reduce Motion enabled and verified in that simulator's Accessibility settings before launch; this suite does not itself set or assert that system setting. Validate motion and route transitions by observation; an automated audit alone cannot verify animation behavior.

The suite does not type or send, read the pasteboard, clear drafts or pair, or intentionally capture screenshots. XCTest result bundles and accessibility audit output can contain live labels and other data; the runner must apply the existing private-artifact policy and avoid public/logged output. Review requested light/dark screenshots separately only after the no-artifact pairing phase; inspect prompt contrast, clipped labels, safe areas and keyboard overlap. Run the keyboard test only when the normal Projects search is present; it never changes its value. At accessibility sizes the tab strip scrolls horizontally; check all five labels and selected traits. The source labels localize dynamically, so checks require nonempty labels rather than English strings.

Priorities beyond this suite:

1. Actual small-phone plus accessibility-size, light/dark, keyboard and VoiceOver navigation across tabs, project row, thread composer, pairing and viewer; automated XCTest audit is not a complete VoiceOver pass. Test both composer focus and project search without editing existing drafts.
2. Reduced Motion setting verified on device; observe cat, navigation and viewer behavior. iPad regular-width native sidebar/badges remain a separate route.
3. Device/release readiness is not established by simulator Debug. `scripts/build-ios.sh sim` uses simulator SDK and installs/launches a booted simulator; the archive path uses generic iOS Release with signing configuration, and export explicitly uploads to App Store Connect. It is not a local-only signed archive/IPA validation path. App plus Island extension have separate provisioning profiles in the manual branch. No signing identities or accounts were inspected and no archive/export/upload was run. The separate `validate-local-release.sh` builds Release locally with signing disabled, checks the bridge hash and records binary hash, platform and any readable embedded entitlements; it never installs, launches, archives, exports or uploads. Run it only from a dedicated source copy. Its source SHA is caller-asserted and must be checked against the archived source receipt separately; unsigned simulator or optional unsigned device builds do not establish signing. A separately authorized device-signing and distribution plan must verify entitlements, profiles, extension signing and release configuration before any distribution.

Source observation: the accessibility-size strip gives each tab at least 90 points inside a horizontal scroll view, so on a small phone not all tabs fit at once. This is intentional scrollable layout, not evidence that the last tab is reachable or that selected state is correctly spoken; the test and manual VoiceOver pass cover that uncertainty. No product source change is proposed without runtime evidence.
