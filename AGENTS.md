# Backplane (Bend)

An agentic hardware development environment: an agent harness with
deterministic viewers for KiCad boards, schematics, and STEP models. It is a
ground-up rewrite of Backplane (formerly a T3Code fork; this repo now lives
at `i2cjak/Backplane`) in [Bend](https://bend-lang.com), so the rules that matter are laws the compiler
checks.

When using Bend:
- run `bend guide` to learn it
- use `LAWS.bend` to keep important rules
- run `bend PROOF.bend` before committing
- parallelize the code whenever possible

## Layout

- `LAWS.bend`: the rules, stated as laws over the real code. Humans own it. An agent may add laws, but never weaken or delete one without the user's explicit consent.
- `PROOF.bend`: a proof of every law. `bend PROOF.bend` must print "All terms check."
- `src/core/`: pure Bend. JSON, S-expressions, the event-sourced thread model, the settle rule, sidebar order, KiCad parsing, scene diff and fade, semver, and the prompt/skills logic. No IO here.
- `src/core/telemetry.bend` (pure planner, wire allowlist and signatures), `src/server/telemetry.bend` (hub-only private queue and sender): tiny install/update/daily-active counts, shared Settings opt-out/reset and tour consent. Compile-only credentials and immutable package channel come from `scripts/telemetry-header.py`. See `docs/telemetry.md`; tests `test/telemetry_test.bend`, `test/tools/telemetry_build_test.py` and `test/tools/telemetry_e2e.ts`. Platform package ingestion remains a separate release gate.
- `src/server/`: the Bend program that owns IO: HTTP/WebSocket, the event store, agent processes, git, file watching, and updates. Its custom effects are JavaScript (`src/server/effects/*.js`): the hub runs on Bun, and has no C.
- `src/app/`: the native window app, which nothing builds any more (its C effects went with the C build; their JS twins answer ENOSYS, so it only type-checks). A Bend window client in the same process as the hub: `nui.bend` (input → state, pure), `layout.bend` (state → draw ops + hit regions), `main.bend` (event loop), `effects/win.js` (the window effects' interface; the X11 window was C).
- `src/gfx/`: the rasterizer. Draw ops become Base's `Image` quadtree in parallel (`raster.bend`); `draw.bend` builds ops; `font.bend` is generated from Spleen 8x16. `text.bend` is system-font text (fontconfig + FreeType were C; on JS, `effects/font.js`, the bitmap font): faces, a glyph cache in Bend state, measure/wrap/draw; a glyph not cached leaves a want op (`Want`, an empty box no tile keeps) that main.bend's `Shell.paint.want` fetches before laying the frame out again, and a code point the face lacks comes from the font fontconfig picks for it (`test/native/glyph_fallback.bend`); `patches/raster-bitmap-shape.patch` adds the `SMask` coverage shape it draws with.
- `src/gfx/mesh.bend`: the 3D viewer's rasterizer and camera. The camera turns freely like SolidWorks, about a board's rectangle centre (its Edge.Cuts box, halfway through its thickness; `Scene3.refit` in face.bend, laws `cam_fit_turns_about`, `scene3_board_pivot`) or a plain model's centre (controls in `nui.bend`, `Drag.mode`/`Key3.act`, laws `view_drag_*`, `view_key_*`); edges are watertight (measured from their first end, so no cracks); a view at rest takes four samples a pixel (a drag draws a half-size draft). Tests: `test/cam_test.bend`; `test/native/pcb3d_frame.bend` writes both kinds of frame.
- `src/gfx/tiles.bend`: frames kept as 64 px tiles, each drawn in its own coordinates; a node whose ops and base are unchanged is kept whole, and the next frame redraws only tiles whose ops or base changed, drawn in parallel from a plan (`Frame.par`: `Tiles.plan`, `Jobs.deal`, `Plan.fill`; laws `frame_par_exact`, `plan_fill_again`, `drawn_get_run`), and a tile the thread scrolled takes the image the last frame drew where it came from (`Past`, `Tiles.seek`; the shift hint is nui.bend's `Hits.slide`, from the thread's lines or else the sidebar's rows, and a wheel notch in either is one tile, `Nui.notch`; the sidebar stops at its end, hit `side-most`) (laws `tiles_again_exact`, `frame_again_exact`, `tile_keep`, `seek_made`). The timeline keeps each entry's laid-out lines the same way (`TL.memo` in `layout.bend`, laws `tl_*`), lined up by entry id first when the page slid or grew (`TL.align.of`, law `tl_align`). There is no "Show earlier" button: the wheel within two screens of the timeline's top shows another page (`Tl.up` in nui.bend, hits `tl-most`/`tl-more`), and back at the bottom the extra pages go (`Tl.down`). Test: `test/scroll_test.bend`; bench `test/native/scroll_bench.bend [EVENTS.jsonl]`. Both compare with `src/core/eq.bend`/`Eq.*`, exact equalities whose soundness is proven, so nothing stale is reused.
- `src/gfx/bitmap.bend`: raw RGB frames (the browser helper's frame file) as an `Image` quadtree, composited into a frame at a place and size.
- `src/core/svg.bend` (pure: SVG path data parsed, written, flattened; laws `svg_*`) and `src/core/icons.bend` (the icon set, Lucide paths, ISC; laws `icons_*`). The window rasterizes them once into `SMask` bitmaps in the glyph cache (`src/gfx/icon.bend`, `Lay.icon`/`Lay.ibutton`); the web writes them as inline `<svg>` (`src/web/icon.bend`). Test: `test/svg_test.bend`.
- `tools/browser/`: `backplane-browser`, a Bun + playwright-core headless Chromium driven by NDJSON on stdin/stdout; raw frames go to a file. Pages are keyed by an owner (`"page"`: a bot's id for a bot's thread, else the thread's id, `BT.World.page`, so every thread drives its own; `""` is the shared page, which Backplane no longer uses), all in one persistent profile (`<home>/browser-profile`); each page's JPEG frames go to `<home>/shots/<owner>.jpg`. Bend side: `src/server/browser.bend` (`Browser.ask_on`, test `test/browser_test.bend`). Protocol in its README; `bun tools/browser/test/pages.ts` tests it. Built by `scripts/build-browser.sh`.
- `src/core/cef.bend` (pure: the embedded Chromium; laws `cef_*`, test `test/cef_test.bend`). Setting `browser.engine` `cef` (chips in the window's settings): the window tells its local hub its X window (`Win.xid`, read once at start; RPC `browser.embed`, accepted only from the in-process window or a loopback link, `Cef.from`), the hub moves the helper to its `cef` engine (server.bend's `Hub.cef.reconcile`, only after the steps `Cef.after` names; state `CefSession` in botnet.bend's `Bn.cef`; info `browser.engine.live`/`.err`, one `browser.page.<id>` per page that exists). Every native operation runs in order on one worker (`CefQueue`); engine replies carry a generation. Layout leaves one `cef` hit for the shown page once it exists (`Page.cef`, none while an overlay covers it) and main.bend's `CefWin.post` places it after each frame (`browser.place` → helper `show`/`hide`). A shield over the page is on while the agent drives; the helper's `shield-click` takes the page over (the same `drive.<page>` state for threads and bots; `tk-handback` carries the page id, `Teach.target`). A restarted helper keeps the engine (`Br.argv`) and the hub shows the placed page again. End to end: `BACKPLANE_CEF=... CEF_DISPLAYS="86 87" bun test/tools/cef_window.ts`.
- `src/core/tz.bend`, `src/core/when.bend`, `src/core/sched.bend`: time for routines (pure). `Tz.*`: a zone as its POSIX rule (`EET-2EEST,M3.5.0/3,M10.5.0/4`: offset at an instant, wall clock, the instant of a wall time with gap/overlap rules, show/iso); `When.parse`: "in 20m", "tomorrow 9am", ISO times in a zone; `Sched.*`/`Zone.*`: the person's zone from settings (`person.tz`, `person.tz.device`, `tz.machine`, `tz.rule.<name>`), `Sched.due`/`slot`/`next` (legacy, zoned once-per-wall-slot, one-time), `Sched.row`/`hint`/`order` for every client's routine list. The hub resolves rules from zoneinfo (server.bend's `ZoneJob`, `Hub.zone.tick`); reminders (`Reminded`) alert through `Remind.after`. Laws `tz_*`, `sched_*`, `when_*`, `notice_remind_*`, `alert_remind_*`; docs/bots.md "Routines". Tests `test/tz_test.bend`, `test/when_test.bend`, `test/sched_test.bend`, `test/routines_codec_test.bend`.
- `src/core/exe.bend`: where the hub's own binary is (pure: `/proc/self/exe` reads "<path> (deleted)" once an install or update replaced the file while the hub kept running; `Exe.path` strips it for a restart, `Exe.child` runs `/proc/self/exe` for plot, tree, inspect and review children so they spawn and stay one version; laws `exe_*`; test `test/exe_test.bend`). Without it a phone's viewer said "No such file or directory" after every deferred-restart install.
- `src/core/locks.bend`: named FIFO locks, projected from append-only `LockChanged` events (`M.Locks.*`). `Locks.*` in hub.bend delivers queued thread grants once through `Lr.send`, defers locked work, and expires retired holders and client leases. MCP `lock_acquire`/`lock_release`/`lock_list`/`lock_cancel`; loopback `/lock/*` and `scripts/bp-lock.sh` for shell callers. Native guards hold matching POSIX flocks via captured children; `BACKPLANE_LOCK_DIR` isolates tests. All clients show Locks on Status and Release/Cancel in Subagents. Tests: `test/locks_test.bend`, `test/tools/locks_e2e.ts`. See `docs/locks.md`.
- `src/core/clipath.bend`: where the provider CLIs are found (pure: the login shell's PATH and the usual install directories (nvm newest first, volta, bun, ~/.local/bin, homebrew...) merged after the hub's own PATH, the probe script and its parser; the server sets PATH with `Env.put` before each detection and re-checks the CLIs present every minute, `Refresh.loop`; laws `clipath_*`; test `test/clipath_test.bend`).
- KiCad over IPC (`docs/kicad-ipc.md`): `src/core/kserve.bend` (pure: a project's server directory and command line, the ready line, the `-bp.N` version check, the 1/5/30 s restart schedule, which server a third project retires, the 18 commands a headless KiCad refuses, the words shown; laws `kserve_*`, test `test/kserve_test.bend`), `src/server/kserve.bend` (the actor: one record per project, at most two servers, requests wait for a server that is starting), `tools/kipc/` (`backplane-kipc`, Bun: nng over `bun:ffi`, protobuf from the runtime's `share/backplane/api.desc`; it also starts the servers and reports their exit; built by `scripts/build-kipc.sh`; test `bun tools/kipc/test/kipc.ts`), the `kicad_ipc` and `kicad_ipc_status` MCP tools (`KIpc.*` in server.bend). Nothing here signals a process: servers end themselves (`--parent-pid`, `--idle-exit`, `kiapi.backplane.Shutdown`). End to end: `bun test/tools/kicad_ipc_e2e.ts`.
- `src/core/client.bend`: the client state and actions both UIs share. Each thread (a bot's too) has its own viewer: kind, path, diff and whether the panel is open live under `<key>:<thread>` in the info map (`Viewer.put`, `Ui.reselect` swaps the panel when the selection moves), and the window keeps each thread's camera and scene (`N.Park` in main.bend's `Kept`). The Browser tab shows the thread's own page (`Lay.page`). `Want.*` binds a machine-switch selection to its destination and generation, and adoption resolves it after installing state; `HubCache.*` keeps the home and last remote hub for immediate display and delta reconnects (`test/hub_switch_test.bend`). Test: `test/view_test.bend`; end to end `bun test/tools/viewers_e2e.ts`.
- `src/core/menu.bend` (pure: where a menu's boxes go: stacked rows, a wrapping flow of chips, rows that fit a height, a clamped scroll; laws `menu_*`) and `src/core/badge.bend` (a project's colour and icon from its settings; laws `badge_*`). The model picker (`Lay.picker` in layout.bend) and the badge editor (`Look.*`) place everything with them. Test: `test/menu_test.bend`. `test/native/ui_snap.bend` renders the window from an event log and an info message to a PPM with no window (`build/ui_snap EVENTS INFO THREAD FLAGS OUT [W H]`).
- `src/core/modelpick.bend`: the web and desktop model picker under the composer (pure: three columns, agent | model | effort; the effort meter's steps (`ModelPick.steps`: the six common ones and any other level the agent takes, those its model does not take disabled), the cursor the keys move (`ModelPick.key`: Tab/Shift+Tab columns, up/down rows, left/right effort), what applying it asks the hub for (`ModelPick.plan`: another agent is one `thread.provider` carrying the model and the effort, hub.bend's `Hub.switch.as`, laws `switch_takes_model_effort`, `switch_effort_offered`, `switch_model_between_turns`). client.bend's `Mpk.*` keep the cursor in the scratch `@mp` while the picker is open (actions `mp-key`, `mp-agent`, `mp-model`, `mp-effort`); view.bend's `View.mp.*` draw it and the chip ("claude / opus / high", Ctrl+M in workspace-keys.js). The phones keep their own picker (`Mob.picker`). Tests: `test/modelpick_test.bend`, `test/model_labels_test.bend`, `test/model_overlay_test.bend`, `desktop/test/workspace-keys.test.cjs`.
- Projects in the sidebar: the search icon opens a filter (`Find.*` in client.bend: form field `pq`, flag `psearch`, actions `proj-find` (on/off/flip), `proj-find-q`, `proj-go`; laws `find_*`); the badge editor's Remove takes two clicks (`Ui.remove_project`, `@rm`, `proj-keep` cancels) and sends `project.remove`; adding a removed project's folder again brings it back with its threads (`Hub.removed_id`). New Thread and Fork are waited for at once (`Made.waiting`, the phones' screen field `making`, laws `made_waiting_*`): the phones open a "New thread" page the moment it is tapped and the hub's thread replaces it (iOS pushes `AppModel.making`, Android `MakingScreen`), so the button is never tapped twice. A project added or made afresh starts with a thread (`Hub.project_add.new`, law `project_back_no_thread`), sent before the reply, and the client that asked goes to it (`Proj.adding` sets `want_new`; the reply clears it). Tests: `test/picker_test.bend`, `bun test/tools/proj_thread_e2e.ts`. Phones: a search field over the list (every hub's at once: `Hubs.everywhere`) and a long press on a project that asks first (`removing` in screen.bend). Tests: `test/project_find_test.bend`, `test/hubs_test.bend`.
- The sidebar (client.bend's Quiet/Active/Menu sections, all four clients): one list whatever machine it runs on (the machine switch sits beside Settings, only with several; phones merge every hub, label projects from a hub other than the focused one, and disambiguate equal names, `Hubs.projects`). The search field is always at the top of the list (`Find.q` holds whenever it has text). Projects with no live thread sink under the live ones, faded, and after `Quiet.days` fold under "Older" (`Side.groups`, flag `old-projects`, action `side-older`). The "sidebar.view" setting "active" swaps in one list of live threads, what waits on the person first (`Urg.rank`: approval, question, failure, finished, stopped, working, idle; pinned ahead within each), then the recently settled, faded and folded under "Settled N" (`Active.rows`, `Active.parts`/`Active.folded`; flag `active-settled`, action `side-settled`, a search shows them; law `active_fold_shut`). A setting (the view swap included) applies to the client's state at once, before the hub echoes it (`Ui.setting.here`; the sequence is left alone). A right-click (a long press on phones) opens a row's or project's menu (`Menu.*`, scratch `@menu`, actions `row-menu`/`proj-menu`/`menu-close`, `row-pin`/`row-archive`...; Delete and Remove ask first); nothing acts on a row by itself. Laws `urg_*`, `menu_*`, `find_always_on`; test `test/sidebar_test.bend`.
- Scratch threads (`M.Scratch` in model.bend): conversations that belong to no project live in the built-in project `scratch` ("Scratch"), which the hub makes at start (`Hub.recover.k` in server.bend, `M.Scratch.ensure`, rooted at `<home>/scratch`; a removed one stays removed). Each scratch thread (a fork of one too) works in `<home>/scratch/<thread>`, set at creation (`Hub.new.wt`/`Hub.new.env`/`Hub.new.outs` in hub.bend, also used by bothub's Give and mcp's launch) and made by the server before anything else runs (BotFx `scratch`, `BotJob.scratch`). They are ephemeral: the tick deletes one left alone for the `scratch.days` setting (1..90, default 7) and the server removes its folder (`Scratch.sweep`, BotFx `scratch-gone`); pinning keeps one, a busy one is never taken. The sidebar never folds Scratch under "Older" (`SRow.scratch`). `/give <refs> [note]` in any thread (client.bend's `Give.is`/`Give.ask`, the send button reads "Give") sends `bots.give {thread, text}`: bothub.bend's `Give.*` hands the conversation (`HD.Hand.give`) to each `>thread` (queued ahead of its next message), `%project` (a new thread there with it queued) and `@bot` (woken with it); a text that names none is refused. Laws `scratch_*`, `give_*`; test `test/scratch_test.bend`.
- `src/core/refs.bend`: references in a message (pure: `@bot`, `>thread`, `%project`, `#room` slugs; what the composer offers, ranked; what a sent message names; the agent's `<references>` block; summaries from the text model, kept as settings `summary.<id>`; laws `refs_*`, `sum_*`, `bot_mention_once`). The composer's popup shows them through the `$skill` rows (`U.Skills.of`, rows named with their sigil), cached per draft edit in the info map (`refs.for`, `refs`). The hub wakes mentioned bots and posts to mentioned rooms (`BH.Bots.hub`); turn ends ask for summaries (`H.Sum.*`, the server's `SumJob`). See `docs/bots.md`. Test: `test/refs_test.bend`.
- `src/core/slash.bend`: slash commands in the composer (pure: the table, Backplane's `/btw` and `/give` for any thread, Claude's `/compact` and `/context` only in a Claude thread; `Slash.typing` is a draft that is one word starting with `/`, `Slash.cmds` those whose name starts with it). The composer's popup (client.bend's `Skills.all`, `Slash.of`) lists them with their text, then the thread's skills as `$name` rows, at most 8; `/` fetches the skills like `$` (`Skills.need`). Esc shuts any popup (`skill-close`, info `sk.off` holds the draft it was shut on, so another edit opens it again; the window's `Esc.menu`, the web's `data-esc`); Tab/Enter/click complete as for skills. Laws `slash_*`; test `test/slash_test.bend`.
- `src/core/links.bend`: links in a message (pure: web addresses, bare or `[label](url)`, and paths to files, bare, in backticks or as a markdown target, with an optional `:12`/`#L12`; `Link.pieces`, `Link.is_path`; laws `link_*`). A link that is not a web address is a file's: a click asks the hub to open it on its machine (`file-open` → `file.open {path, how}`, the hub's `FileJob` runs `Link.file.cmd`: the system opener, or "reveal" through the desktop's FileManager1, Finder on a Mac), a right-click (a tap on phones) opens its menu (client.bend's `Menu.file`, `@menu` `f:<path>`: Open, Show in folder, Copy path; `file-menu`, `file-reveal`, `file-copy`). A relative path is in the thread's folder (`Flink.abs`, `Link.file.abs`). Tests: `test/links_test.bend`, `test/sidebar_test.bend`.
- Markdown: one parser for all four clients, `Md.render` in `src/web/dom.bend` (paragraphs, headings, lists, ordered lists keeping their numbers (`li value`), blockquotes, rules, fenced code, tables (a `|---|` row makes the first row the head: `Md.headed`), inline code, bold, italics, links; laws `md_*`, test `test/md_test.bend`). The web writes its nodes; phones get them as JSON (`Mob.nodes`, an item's number as `n`) and draw them natively (`Markdown.swift`, `Markdown.kt`: a table is a grid, columns as wide as their widest cell up to 240, scrolling sideways); the window lays them out as lines (layout.bend's `TL.block`: a table as kind 18/19/20 lines, each column as wide as its widest cell, the wide ones shrunk to the panel, cells wrapped; quotes kind 22, rules 21).
- `src/core/fold.bend`: runs of tool calls folded into one row (pure: groups, labels, per-entry roles; open state is `fold:<first id>` in the Ui info map, the "fold" action; laws `fold_*`). The window applies the roles each frame over the memo (`TL.entries.mr`, kind 14 lines), the web in `View.entries`. Test: `test/fold_test.bend`.
- `src/core/edit.bend`: text editing for the window's fields (word and line motions, ranges, undo history); `nui.bend`'s `Ed` maps keys onto it. The composer moves by the lines it shows: Up/Down and a press or drag in it leave a request in the scratch (`@cq`, nui.bend's `Cq`) that main.bend places after each event with the font (`Comp.pend` in layout.bend, over `Edit.starts`). Test: `test/edit_test.bend`. Thread text selection is `TSel` in `layout.bend` and `Sel.*` in `nui.bend` (test `test/select_test.bend`).
- One hub per home: a hub holds an exclusive flock on `<home>/hub.lock` for its whole life (server.bend's `Lock.*`, `src/server/hublock.bend` + `effects/hublock.js`, pure answers in `src/core/onehub.bend`, laws `onehub_*`), taken before anything touches the event store; the file says `<pid> <port> flock`. The kernel drops the lock when the process dies (SIGKILL too), so a stale file blocks no one; the descriptor is close-on-exec, so no child holds it, and a restart in place hands it over (the host's `Sys.exec`; the new image takes it back from `BACKPLANE_HUB_LOCK_FD`). A window started while one runs for the same home joins it over its port (main.bend's `Start.hub`; the address is the client's `local.hub`, and a dropped link is tried again); `--headless` and `backplane-serve` print "a hub already serves <home> (pid P, port N)" and exit 1. A file without `flock` is an older hub's, believed while its pid lives (`Lock.find.sh`). Two hubs on one log each kept their own state, so what one client sent never reached the others. End to end: `bun test/tools/onehub_e2e.ts [BINARY] [WIREDIR]`.
- The command line is strict (`src/core/cli.bend`, `Cli.of`, laws `cli_*`, test `test/cli_test.bend`), checked first in both mains before any other IO: the hub's flags are `--home DIR --port N --host ADDR --web DIR --no-tailscale --tailscale --tailscale-https --headless --foreground`, and the children's (`--review`, `--plot`, `--plot-tree`, `--plot-info`, `--render`) come first. An unknown flag, a word, or a flag without its value prints the usage to stderr and exits 2; `--help`/`-h` prints it and `--version` the version, exit 0. None of them opens the home, binds a port or opens a window. A new flag goes into `Cli.kind`.
- Stand-in agents: a test hub gets its stand-ins as `BACKPLANE_AGENTS=<dir>` (`src/core/standin.bend`, server.bend's `Agents.only`): `<dir>` goes first on PATH and `<home>/standin-blocks` second, a block for each of claude/codex/grok/muse that `<dir>` has no runnable file for, which fails the turn with "<dir> has no runnable <cli>" (exit 127). The real CLI later on PATH (or in the login PATH clipath.bend merges in) is never run. A `<dir>` that is not a folder stops the hub. Every `test/tools` e2e passes its `fake` folder this way. Such a hub does not sync KiStack from GitHub (below) unless `BACKPLANE_KISTACK_SOURCE` names a local copy or `BACKPLANE_KISTACK_SYNC=1`; a test hub without stand-ins sets `BACKPLANE_KISTACK_SYNC=0`.
- KiStack's skills (`src/server/kicad.bend`'s `KiStack.*`): at every start, after the hub serves, its newest commit is synced in the background into `<home>/kistack` (`KiStack.sync`, two POSIX scripts; only `skills/**` and `LICENSE`, links refused, our own `plugin.json`, a `REVISION`, swapped in by rename; skipped on Windows, on a copied log and with `BACKPLANE_KISTACK_SYNC=0`; `BACKPLANE_KISTACK_SOURCE` is a local `.tar.gz` or folder used instead of GitHub). That copy wins once complete, for Claude's `--plugin-dir` (checked at each Claude start, server.bend's `Claude.job`) and the `<skills>` block and `$` list (`Skills.scan`); else the copy bundled at build time (`scripts/build-kistack.sh`, `deploy/kistack.lock`). Test: `test/agent_test.bend`.
- `src/core/qr.bend`: QR codes (pure: byte mode, level M, versions 1-40, the least-penalty mask; rows of '1'/'0'; `Qr.link` wraps a pairing link as `backplane://pair?url=…` so a phone's own camera opens the app; `Qr.path` for SVG; laws `qr_*`). The hub sends its pairing link's code as info `pair.qr` (server.bend's `Info.net`); Settings' "QR code" (flag `pairqr`, client.bend's `Pair.qr`) shows it in the window (`Pq.*` in layout.bend, an overlay a click puts away), on the web (`View.pair.qr`, inline SVG) and on phones (the row's `qr`, `Mob.set.pair`). Phones scan it from the pairing screen and Hubs: iOS with AVFoundation (`Pair.swift`), Android with Google Play services' code scanner (`Pair.kt`). Test: `test/qr_test.bend` (matrices from python-qrcode, decoded with zxing).
- `src/core/tailnet.bend` (pure: owner trust from `tailscale whois`, the owner's machines from `tailscale status`) and `src/app/link.bend` (a WebSocket client shaped like a hub, so the native window can switch to another machine's hub). emission alone is never a passing test. The intentionally red

gate (`test/tools/mobile_cache_identity_gate.py`), not the positive suite.
`python3 -m unittest discover -s test/tools -p test_runner_test.py` verifies

Trying a branch without CI or a release (use this, not a release, whenever the user wants to see or try a change):
- `scripts/dev.sh` builds the hub and web client into `build/dev` (about a minute; seconds when the server is unchanged) and runs them beside the installed Backplane: port 3788, home `~/.backplane-dev`, no tailnet, no self-update. ## Bend traps (learned here, keep adding)

- A `match` scrutinee must be a parameter or pattern-bound variable, even in a multi-match. Pass computed values (`String.eq(a, b)`) to a helper def that matches on its parameters.
- A def must be defined above its uses. Forward `law` declarations don't help: live code can't call an unfilled law.
- No mutual recursion. When a recursive walk needs a per-element decision, compute it in a non-recursive step and recurse on the tail: `go(t, step(h, st))`. For look-ahead, pass the head's precomputed flag as a parameter: `go(t, hit(t, k), k)`.
- In a recursive call the shrinking argument comes first. Arguments before it must be passed unchanged.
- Operators need a type: `(a + b : U32)`. Division too: `((x * 255 : U32) / 200 : U32)`.
- Inside `do`, only `x : T <- m`, `x : T = v`, and steps are allowed. Destructure in a helper def.
- `A & B` is affine. For a reusable pair in a `List<&2, …>`, declare a small `is Data` type (like `KV`).
- Multi-arg calls on List/Maybe take the quantity first: `List.head(&1, String, xs)`, `Maybe.default(&2, U32, m, d)`.
- `bend page.html -o dist` writes an empty chunk when a .bend file fails to check. Always `--check-only` first (`scripts/check.sh` does).
- `Nat.max`/`Nat.min` recurse once per unit: at epoch-second scale they overflow the stack. Use `Time.max` (model.bend) or `Bool.pick(Nat, Nat.is_ge(a, b), a, b)`. `Nat.add/sub/mul/div/mod/cmp/is_*` are native and safe.
- Never choose between screens, overlays or lists with `Bool.pick` or `Out.when`: every hidden screen gets laid out each frame (the thread view cost 70 ms that way). Match on the Bool in a helper (`Lay.main.k`, `Lay.proj.if`, `Proj.items.q`, `Ops.picked.k`).
- `Bool.pick(T, c, a, b)` evaluates both branches, so each variable in them counts as used twice (mark it `+`). When a branch consumes something affine, match on the Bool in a helper instead.
- A recursive call in both branches of a `Bool.pick` (`Bool.pick(L, c, h <> go(t), go(t))`) doubles the work per element: 2^n. It passes a test with a few items and hangs on real data. Match on the Bool in a helper (`Stats.prefix.k` in core/perf.bend).
- Multi-match scrutinees must follow binder order: parameters in declaration order, then pattern-bound names in binding order.
- `List.map` and `List.filter` accept only `List<&1, _>` or need `~` templates with closed arguments. For `List<&2, _>`, write the recursion.
- IO loops: a looping def passes a continuation lambda that calls itself with less fuel (`r => Helper(r, x2 => Loop(f, x2))`). The helper must never name the loop, or the two become mutually recursive.
- Put the shrinking argument first even in IO loops (`Hub.commit(cs, h, …)`, not `(h, cs, …)`).
- `where` is a keyword.
- A let (`+x = …`) may not come before a `match` on a parameter. Put the lets inside the case, or compute them in a wrapper def and pass them in.
- `++` joins Strings only. Lists join with `List.append(&2, T, a, b)`; for many, a small concat over a list of lists.
- A float literal bound by a let needs a type: `+d = {0.635 : F32}`.
- `IO.args()` gives a `List<&1, String>`; copy it into a `List<&2, String>` with a small recursion to use it more than once.
- Constructor ids of module types are path-qualified in C (`CID__HOME_..._WKEY`), so an effect cannot build them. Effects return Base types (lists of U32, strings, tuples) and Bend decodes them (`Win.decode`).
- Names Base already uses (`Event`, `App`, `Kind`) cannot be redeclared.
- `Tools`: `scripts/bend-order.py FILE` fixes def order (and reports mutual-recursion cycles); `scripts/bend-reuse.sh FILE` marks binders reported as consumed twice.
- Rewrites: `%e : P` with `e : {a == b}` turns a goal `P[_ := b]` into `P[_ := a]`. Use `Equal.sym` to flip direction and `Equal.trans` to chain.
- A destructuring let of a call (`K{a, b} = f(x)`) is a match on a computed value and is rejected. Build trees bottom-up (pair a list level by level, `Tab.up` in glb.bend) instead of returning `(tree, rest)` pairs.
- `is` is a keyword too: a parameter named `is` fails to parse. So is `def` (`+def: String` fails with a bare "Error:").
- Bits to float: `match u: case U32{w}: F32{w}` reinterprets a U32 as F32 at no cost (`Glb.f32`); `F32.bits` goes the other way.
- `IO.args()` answers `List<&1, String>`; copy it into a `List<&2, String>` by recursion before reading it twice. Under Bend 2.0.36 it starts with the program's name: programs read `src/server/argv.bend`'s `Argv.args()` (the mains go through `Rvc.main`).
- Random access into big byte lists: turn them into a balanced `Data` tree once and walk ranges (`Words.range`), never `drop` per lookup.
- A multi-match that discards a cons tail with `_` next to another scrutinee fails ("_ consumed more than once"): bind it (`case +h <> +r True{}:`).
- Only tail calls are free: a walk that builds its result outside the recursive call (`String.repeat`, `Utf8.encode_onto`, `Json.items`) overflows the stack around a few hundred thousand steps. For big inputs, push onto a reversed accumulator and reverse once (`Enc.go` in cbor.bend).
- `Bool.and`/`Bool.or` are strict: both sides are always computed. An `Eq.*` over a list compares all of it.
- `U32.shr(x)` shifts by one; `U32.shrn(x, n)`/`U32.shln(x, n)` take a Nat count.
- A `+n: Nat` parameter makes the `1n+k` predecessor reusable too; with a plain `n`, `k` may be used once.
- In dash (`/bin/sh`), `${d#~/}` expands the `~` first and strips nothing; use `${d#??}`.
- The glyph cache's string-keyed `Map` is slow per glyph; `Text.get` reads ASCII from the face's `GTab` (filled by `Face.tabled` once warmed).
- A long-lived native process gets slower at the same allocation-heavy work each time it repeats it, memory flat (bendlang/bend#1007: free chains lose address order; a board parse 0.2 s → 1.6 s over six runs). Keep big repeated work out of the hub: parse in a child process (`backplane --plot`, src/server/plot.bend) and keep bulky data out of hub memory (plot info tables live in files). `BACKPLANE_BENCH_RUNS=6 build/plot_bench FILE` shows it.
- `Nat.read` (and `Maybe.map` over it) in anything a law normalizes makes `bend PROOF.bend` crawl for minutes. Parse digits yourself (`Switch.num` in model.bend, `Tag.num` in hub.bend), and time a new law alone before the full run.
- A hub started on a copy of a real `events.jsonl` (to measure with real data) resumes every turn that was running in it as a live agent in the real folders (`Hub.recover.carry`). Run such a hub with `BACKPLANE_AGENTS=<a folder of stand-ins>` (as in `test/tools/*_e2e.ts`): a PATH without `claude` is not enough, the hub merges the login shell's PATH and `~/.local/bin` in after its own (core/clipath.bend). Run it with `--foreground` so its PID is yours.
- Launch time: nothing slow may run before the window opens (probes, network, full log copies). Start it after, in the background, and serve the last answer meanwhile (`src/core/boot.bend`). `test/native/boot_bench.bend` times start-up and frames on a real log.
- CPU forks are dealt out once, not stolen: fork over one flat balanced tree of work items (all primitives of all nodes) rather than nesting forks per group; nested forks inside a heavy group barely spread.
- The runtime deals out a value's work at the first fork it meets while evaluating it, and everything after runs where it was dealt. A spatial quadtree whose busy part sits in one corner (a thread's text) ran on one core however many there were. Collect the heavy items into a list, deal them round robin into a balanced tree (`Jobs.deal` in tiles.bend), and evaluate that tree in its own `do` binding so its forks are the first ones (main.bend's `Shell.present`). `test/native/par_bench.bend` shows each shape on 1 and 16 cores.
- Fork arguments are fine to be cheap references: the runtime's rc counts make a shared list read by many lanes cost atomics, but the balanced tree above still spread 10x.
- The phones' bundle gets native `String.cmp`/`String.eq` (`scripts/bridge-native.py`, run by `scripts/build-mobile.sh`; it stops the build if Bend's output changes shape): Bend's own compare a char at a time was over half of every phone screen. Bench the phone client with no hub: `test/tools/phone_screen_bench.ts` (screens) and `test/tools/phone_stream_bench.ts` (streamed text), `BUN_JSC_useJIT=0`, on a state from `launch_bench.ts cold`.
- Streamed text: the hub merges a read's run of Claude text deltas into one (`Delta.merge` in hub.bend) and a read that ends mid-stream waits `Delta.pace()` ms before the next, so a fast agent sends a few frames a second, not one a token (`test/delta_test.bend`); a phone builds no screen for another thread's delta (`Hubs.shows`, laws `hubs_delta_*`), and a screen the app dropped as stale is owed to the next frame (`owe` in bridge.js and both Engines). WebSockets are `TCP_NODELAY` (the C hub's `sock_dup` set it; host.js's does not yet).
- A throwaway hub on a copy of the real log resumes the turns that were running in it (a second agent in your worktree): append a `SettingSet` of `restart.continue` to `off` to the copy first.
- Every hub on a copy of a real log runs with `BACKPLANE_COPY=1` (`src/core/copy.bend`, laws `watch_copy_*`, `copy_*`; test `bun test/tools/copy_e2e.ts HUB WIRE`). Without it the copy re-launches every `work_run` still open in the log (a copied home has no `work/<id>/started`: one re-ran a loop polling the live hub, another waited to move a folder of live coordination state), and could signal real processes through `pid` watches. With it the hub launches, re-launches and signals no watched work (every watch reads as gone), runs no outs that act outside its home (deploys, restarts, updates, pushes, far pushes and launch reports, named locks, git that writes, bot replies), runs no network command (`curl`, `gh`, `ssh`, `git push`/`fetch`...), refuses `deploy_main`/`deploy_restart`, and runs agents only as stand-in blocks (an empty `<home>/copy-agents` when `BACKPLANE_AGENTS` is unset). It says so in its first log lines.
- The phones' kept-state key (`scripts/state-key.py`) hashes only the types the kept `Hubs` value can hold (`--types` lists them); a new key makes every phone drop its state and fetch the hub's whole log, so don't change those types lightly.
- `backplane --version` prints the version and exits; any unknown argument exits 2 without starting anything (`src/core/cli.bend`). An older installed binary still starts a hub on the live home for any argument: ask a running hub's `/hello` instead.
- In the JS build (web, phones) a Bend `String` is a JS string: matching `SCon` is `codePointAt` + `slice`, and `String.eq`/`String.cmp` rebuild both strings as they go. Comparing or walking long text char by char is quadratic on QuickJS (Android). Don't compare message texts per screen; find cheaper keys or keep the walk out of the per-screen path.
- In the JS build a string grown a char at a time (`SCon{c, acc}`) is a rope: the next `codePointAt` on it copies all of it. Reading the head of an accumulator at every char (links.bend's `Link.word` did, for every char of a streamed reply) is quadratic; ask only when needed (match on the cheap test first).
- An equality over a quadtree (`Eq.image`) guarded by `Bool.and` walked the viewer's whole base at every tile level each frame, changed or not. Compare the cheap part first and the image only when it matches (`Eq.tile`), and carry the verdict down the tree (`Eq.image.go`).
- Shifting a quadtree image by a few pixels (to reuse a panned base) cost more than drawing it again: every node moves off its grid. Draw again in parallel instead.
- In JS, a Bend value is objects nested once per list cell (tens of thousands deep for a log). Anything recursive over it overflows the engine's stack: `JSON.parse` with a reviver lost the phones' kept state at every launch. bridge.js writes the state flat (`flat`/`unflat`, no recursion); time a launch with `test/tools/launch_bench.ts` (`BUN_JSC_useJIT=0`).
- Base's `String.split` recurses once per character too: `Img.paths` split every long reply that named an image that way, the phones' JS engine ran out of stack inside `recv`, and the hub's whole frame was lost (a message sent then never showed in that thread). `Img.words` cuts words in one tail-recursive walk and drops a word over `Img.long()`. Replay a real log through bridge.js under the phone's limits to find these: `BUN_JSC_useJIT=0 BUN_JSC_maxPerThreadStackUsage=4194304`.
- Base's `String.to_lower`/`to_upper` recurse once per character outside a tail call. On a long message they overflowed the phones' V8 sandbox, which crashes natively (no RangeError) and took the Android app with it. Never lower a whole message text; look at the few characters you need (`Img.may` in images.bend). Android now starts the client again in QuickJS if the sandbox dies (`Engine.eval`, `Core`'s `onReset`). Replay a phone launch on real data at a small stack to find these: `node --stack-size=500` with `test/tools/launch_bench.ts`.
- A join's chunks are split, joined, encoded and sent in the host (`H.Sock.send_items`, host.js's `ji_*`: the writer's `WItems` lines as `OB.Items.texts.s` frames them, JSON text straight to the same CBOR bytes as `W.Ws.cbor`, checked line by line and chunk by chunk on real logs by `test/native/cbor_frame_test.bend EVENTS.jsonl`): Bend's encoder sent a 100 MB log at ~1.5 MB/s, and measuring and joining each frame's lines in Bend cost more than encoding. Live frames still go through `Ws.cbor` (the writer counts their bytes). The hub walks the log's length only when a join's next 2000-line window is due (`Boot.k.rest`), not per 64-line chunk: per chunk it made a join quadratic.
- The hub must not read the text of log lines (`String.length`, joining, parsing) per chunk or per frame: a log line is shared, and reading a shared String's characters cost ~1 µs a character (a join's 128 KB chunk took 200 ms on the hub, and every other client waited). Count lines, hand the list to the writer (`WItems`), and let it put the frame together once (core/outbox.bend, server.bend's `Hub.boot`).
- The event loop polls sockets only when no fiber can run: a fiber that always has work (a join's chunks back to back, a reader decoding a ping flood) starves every request. Space repeated work out (`Self.post.later`) and keep per-frame work O(frame): `Ws.decode` once checked `List.length` of the whole buffer per frame (`Ws.has` now), so 20000 pings froze the hub for 7 s. `bun test/tools/stall_e2e.ts` measures both.
- The hub runs on macOS too (darwin-arm64 and darwin-x64: `backplane-serve` as `backplane`, no window; cross-built on Linux by `scripts/build-js.sh`, since bend's emit needs more memory than a macOS runner has, and smoke-tested on the Macs by CI's `js-native`). Shell it runs must not assume GNU or Linux: macOS has no `timeout` (use `Port.tmo()`'s `tmo SECS CMD` in a script, or `P.Proc.run("sh", Port.timeout([SECS, CMD, ...]))`; src/core/port.bend), no `setsid` (perl's `POSIX::setsid`), no `realpath -e`, `find -printf`, `stat -c` or `/proc`. Try a change to such a script on a Mac (`hs-mac-mini` has bend and bun; `scripts/build.sh && scripts/smoke.sh` there).
- A `Bool.pick` whose other branch parses (`Review.label`/`Review.say`: `J.Json.parse(summary)` for every act, review or not) parses every frame. Match on the condition in a helper before parsing (`View.act.spans`).
- `Bool.and(a, b)` in a recursive equality walks everything even after a mismatch. Carry the verdict as a parameter so the walk stops (`Eq.ops.go` in tiles.bend) and prove it once (`ops_go_sound`).
- Bend 2.0.36 (the pin): Base owns the constructors `Look`, `Scroll`, `Ready`, `Wait` (type `Poll`), so a type cannot declare them (ours: `DeskView`, `CatLook`, `BoardLook`, `ScrollEnd`); a def name's dot-separated parts cannot start with a digit (`Nui.key.view3`, `Ob.body.s0`); `Chan.send` answers `Result<&1, &1, T, Unit>` (not Bool); `TCP.listen(host, port)`; a JS effect twin registers each def with `io_eff(CID(Def.Name), fn)` at its end (no need argument; the function parks itself). A program that relies on foreign code (any C/JS effect) prints `SOME PROOFS FAIL` / `N defs rely on unsafe or foreign code` and exits 1 under `--check-only` and `bend PROOF.bend` even when all checks pass: scripts/check.sh accepts exactly that and nothing else.

- Bend 2.0.36's JS target keeps a `Nat` as a Number inside and hands it to JS as a BigInt, so every exported def a JS file calls walks each argument and its answer whose type holds a Nat (in, out, and the argument back). bridge.js hands the whole client state (`Hubs`, every hub's log) to every call, host.js its `Ui`: each frame (and each web keystroke) walked it several times and a phone's cold join went quadratic (a real log: 93 s with no JIT instead of 12, minutes of an empty list on an iPhone). `scripts/js-unmarshal.py TAG FILE...` makes a type's two marshallers return their value (`hubs.Hubs` in build-mobile.sh, `../core/client.Ui` wherever the web is built; the state stays in Bend's form on the JS side, and bridge.js's `unflat` loads naturals as Numbers) and stops the build if it does not find exactly two. A new export that takes or answers a big Nat-holding value from JS pays the same walk. The kept-state key hashes `bend version`, so a Bend upgrade makes every phone fetch every hub's whole log: run `bun test/tools/phone_cold_e2e.ts BINARY BRIDGE` (a cold join at the phone's stack, no JIT: no throw, flat cost per frame, the screen's iOS fields) before shipping one.
- A def the phones fold on every event must not walk the whole log outside a tail call: `Switch.count` (a `ProviderSet`) did, overflowed the phones' stack on a real log, and the frame was lost (the join never caught up). Count from the thread's `State.mine` with an accumulator.
- `--check-only` reports some errors as a bare "Error:" with no message, at the def after the cause or at a def with the same name: a def declared twice (`Bom.keep` twice in one file), a type name another module already has (`Cols` in qr.bend and bom.bend), a `let` without its type inside `do` (`+x = v` needs `+x : T = v`). Running the file (`bend test/x_test.bend`) names a duplicate ("duplicate declaration").

## House rules

- Developing (anything that gets compiled) ends the same way every time: test it (`scripts/check.sh`, the tests and e2e checks it touches), open a PR, merge it, then update every development server in use from the merged `main` (`scripts/dev.sh install h@backplane`, then `scripts/dev.sh install` here, last), and if the phone apps changed (`src/mobile/`, `mobile/`, anything bridge.js is built from), put a new build on TestFlight (`scripts/build-ios.sh archive`, `mobile/README.md`). Check each server reports the new version (`/hello`) and is listening. Never cut a release (a `v*` tag) for this; releases happen only when the user asks for one.
- Every feature matches everywhere: the native window, the web client, and both phone apps (iOS and Android). A feature is not done until all four have it, driven by the same Bend defs, and each is built (and tried where a device or simulator is at hand).

- Never kill processes by name or pattern; only PIDs you captured.
- The binary refuses unknown flags (exit 2) and a second hub on a home (exit 1), but still never run the installed `backplane` to probe it: without `--home` a good flag set starts the live hub, and older installs ignore unknown flags. Ask `/hello`; test with your own build, a temp `--home`, a port 3799+ and `--no-tailscale`.
- Never write to live user data (`~/.backplane-bend/`). Tests use a temp `BACKPLANE_HOME`.
- Persisted events stay decodable forever. Add event variants; never change the meaning of an existing one.
- No continuous repaint loops. The viewer animates only while a fade is in flight, then stops requesting frames.
- The UI is dumb: every decision (order, settle state, fade alpha, what's visible) comes from a Bend def with a law behind it where possible.
- Square corners, minimal copy, no decorative headings.
- Before pushing, verify the GitHub account (`i2cjak`), the remote, and the branch.

## Links

- A link you give the person to something served on a machine (a dev server, preview, review page, dashboard) must open from their other machines on the tailnet: `localhost` and `127.0.0.1` open only on the machine that serves it. Your own probes (`curl 127.0.0.1:3788`) stay on loopback.
- Name the machine by its MagicDNS name, `<machine>.<tailnet>.ts.net` (the serving machine's own is `Self.DNSName` in `tailscale status --json`, minus the trailing dot). `<machine>` and `<tailnet>` are placeholders: give a link only with the real names filled in, never an example name.
- Keep the server on `127.0.0.1` and share it with Tailscale Serve: `tailscale serve --bg --https=<free port> http://127.0.0.1:<port>`, then give `https://<machine>.<tailnet>.ts.net:<free port>/`. Serve is tailnet-only, over HTTPS, under the tailnet's access rules; `--bg` keeps it across reboots, so ask the person first, and turn it off when done (`tailscale serve --https=<free port> off`). Leave port 443 alone (the hub's `--tailscale-https` serves there) and never run `tailscale serve reset`, which drops the hub's too.
- Never bind a server to `0.0.0.0` to make a link work, never use `tailscale funnel` (it publishes to the internet), and never turn off a server's sign-in or TLS for a link.
